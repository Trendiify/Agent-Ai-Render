# سرور اجرای کد (Executor) برای ایجنت

یک سرور کوچک که ایجنت کدهایش (پایتون، نود، bash) را **قبل از تحویل به تو** روی آن اجرا و تست می‌کند. خطا را می‌بیند، اصلاح می‌کند و فقط بعد از موفقیت تحویل می‌دهد. فایل‌هایی که کد می‌سازد (Excel، Word، PowerPoint، PDF، نمودار، zip) هم از همین‌جا به تلگرام می‌رسد.

بدون وابستگی است (فقط Node)، و روی Render، Railway (با اکانت قانونی)، Koyeb یا هر VPS اجرا می‌شود.

## فایل‌ها

| فایل | کار |
|---|---|
| `server.js` | خود سرور (اجرای کد + نگهداری فایل‌های کاربر) |
| `extract.py` | استخراج متن از PDF، docx، xlsx، pptx، zip و متن/CSV (با تشخیص کدگذاری فارسی windows-1256) |
| `render_page.py` | رندر یک صفحه‌ی PDF به تصویر (برای PDF اسکن‌شده با مدل بینا) |
| `Dockerfile` | ساخت ایمیج (پایتون + openpyxl، python-docx، python-pptx، pandas، pillow، requests، beautifulsoup4، reportlab، matplotlib، pypdf، pypdfium2) |
| `render.yaml` | تنظیم خودکار روی Render |

## نصب روی Render (رایگان)

### ۱) بارگذاری روی گیت‌هاب
1. در گیت‌هاب یک ریپوی جدید بساز (مثلاً `agent-executor`). **Private** هم می‌شود.
2. **Add file ← Upload files** و این فایل‌ها را بکش: `server.js`، `extract.py`، `render_page.py`، `Dockerfile`، `render.yaml`، `.dockerignore`
3. **Commit changes** بزن.

### ۲) ساخت سرویس در Render
1. در [render.com](https://render.com) ثبت‌نام کن (با حساب گیت‌هاب ساده‌تر است) و گیت‌هاب را وصل کن.
2. **New +** ← **Web Service** ← ریپوی `agent-executor` را انتخاب کن.
3. مقدارها:
   - **Language:** `Docker`
   - **Instance Type:** `Free`
4. در بخش **Environment Variables** یک متغیر اضافه کن:
   - `EXEC_TOKEN` = یک رشته‌ی تصادفی بلند (حداقل ۱۶ حرف، ترجیحاً ۴۰). این رمز ارتباط ورکر با سرور است.
5. **Create Web Service** را بزن. ساخت اولین بار چند دقیقه طول می‌کشد (نصب کتابخانه‌ها).
6. وقتی وضعیت **Live** شد، آدرس سرویس را کپی کن (مثلاً `https://agent-executor-abcd.onrender.com`).

### ۳) وصل کردن ربات
در کلودفلر، ورکر ربات ← **Settings ← Variables and secrets**:

| نام | نوع | مقدار |
|---|---|---|
| `EXEC_URL` | Text | آدرس سرویس Render (بدون `/` آخر) |
| `EXEC_TOKEN` | **Secret** | **همان** رشته‌ای که در Render گذاشتی |

**Deploy** بزن و در تلگرام بنویس:

```
/exec
```

اگر سرور خوابیده باشد، «⏳ دارم بیدارش می‌کنم» می‌آید (حدود ۱ دقیقه) و بعد نتیجه‌ی تست: `exitCode=0` و «سلام از سرور آزمایش».

### ۴) امتحان کن
> یک فایل Excel بساز با جدول ضرب ۱ تا ۱۰ و برام بفرست

ربات باید: کد را بنویسد ← روی سرور اجرا کند ← فایل `.xlsx` را بفرستد.

## فایل‌های کاربر (اسناد)

علاوه بر اجرای کد، این سرور فایل‌های بزرگ و PDF را برای ربات می‌خواند:

| مسیر | کار |
|---|---|
| `POST /doc?name=...` | آپلود فایل (تا ۲۵ مگابایت) و استخراج متن |
| `GET /doc/:id/text?offset=&length=` | خواندن تکه‌ای (حداکثر ۳۰ هزار کاراکتر در هر درخواست) |
| `GET /doc/:id/search?q=` | جستجوی عبارت با متن اطراف |
| `GET /doc/:id/page?n=` | رندر صفحه‌ی n از PDF به JPEG |
| `POST /run` با `"input": id` | قرار دادن فایل کاربر در پوشه‌ی اجرا برای تحلیل با pandas |

- حداکثر ۵ فایل همزمان، هر کدام یک ساعت می‌مانند؛ قدیمی‌ها خودکار کنار می‌روند
- متن استخراج‌شده تا ۶ میلیون کاراکتر نگه داشته می‌شود
- PDF اسکن‌شده (بدون لایه‌ی متنی) با `note: scanned` مشخص می‌شود
- حافظه‌ی ۵۱۲ مگابایت برای PDFهای خیلی سنگین یا Excel با میلیون‌ها ردیف ممکن است کم باشد

## بیدار نگه داشتن (اختیاری)

Render رایگان بعد از ۱۵ دقیقه بی‌کاری می‌خوابد و بیدار شدنش حدود یک دقیقه طول می‌کشد. ربات خودش منتظر بیدار شدن می‌ماند، ولی اگر نمی‌خواهی صبر کنی:

1. متغیر `EXEC_KEEPALIVE` = `1` را در ورکر اضافه کن.
2. در **Cron Triggers** ورکر یک کرون دوم اضافه کن: `*/10 * * * *`

این هر ۱۰ دقیقه یک پینگ می‌فرستد. سقف رایگان Render ماهی ۷۵۰ ساعت است و یک سرویس همیشه‌روشن حدود ۷۲۰ ساعت مصرف می‌کند، پس **فقط یک سرویس** را می‌توانی همیشه روشن نگه داری. این روش رایج است ولی Render تضمینی برایش نمی‌دهد.

## امنیت (مهم)

- همه‌ی مسیرها (به‌جز `/health`) فقط با `Authorization: Bearer EXEC_TOKEN` کار می‌کنند.
- **هیچ رمز یا توکنی روی این سرور نگذار** (به‌جز خود `EXEC_TOKEN`). کد کاربر در محیطی بدون متغیر محیطی اجرا می‌شود و `EXEC_TOKEN` را نمی‌بیند (در تست‌ها تأیید شده).
- اجرا با کاربر عادی (نه root)، با سقف زمان (۵ تا ۶۰ ثانیه)، سقف حجم خروجی و فایل، و یک اجرا در هر لحظه.
- ربات این‌طور رفتار می‌کند:
  - کد **بی‌خطر** که خودش در همین نوبت نوشته (بدون استفاده از شبکه/فرایند و بدون خواندن چیزی از وب یا فایل) → مستقیم اجرا می‌شود
  - هر کد با **شبکه، subprocess، نصب بسته یا bash**، و هر کدی در نوبتی که محتوای بیرونی خوانده شده → **اول کد را نشان می‌دهد و دکمه‌ی تأیید می‌خواهد**
- سرور به اینترنت وصل است (برای `pip install` و درخواست‌ها)، پس کد تأییدشده می‌تواند از آن سوءاستفاده کند. به همین دلیل کد شبکه‌ای همیشه تأیید می‌خواهد. **هر کدی را قبل از تأیید بخوان.**

## محدودیت‌های رایگان

- فقط ۰٫۱ پردازنده و ۵۱۲ مگابایت رم: برای تست‌های سبک عالی است، برای محاسبات سنگین یا pandas روی داده‌ی بزرگ نه
- دیسک موقت است؛ فایل‌ها بعد از هر اجرا (و ۱۰ دقیقه بعد) پاک می‌شوند
- شروع سرد حدود یک دقیقه
- مرورگر روی این سرور نصب نیست (برای مرورگر از Browser Rendering کلودفلر استفاده کن)

## رفع مشکل

| مشکل | راه‌حل |
|---|---|
| `/exec` می‌گوید تنظیم نشده | `EXEC_URL` و `EXEC_TOKEN` را اضافه کن و Deploy بزن |
| `HTTP 401` | `EXEC_TOKEN` در ورکر با Render **یکی نیست** |
| بعد از ۹۰ ثانیه بیدار نشد | لاگ Render را ببین؛ احتمالاً ساخت ایمیج شکست خورده یا هنوز تمام نشده |
| `HTTP 429 busy` | یک اجرای دیگر هنوز در جریان است؛ چند ثانیه بعد دوباره |
| `ModuleNotFoundError` | کتابخانه در `Dockerfile` نیست؛ اضافه کن و دوباره Deploy کن (یا کد با `pip install` + تأیید) |
| سرویس Render وسط کار restart می‌شود | حافظه‌ی ۵۱۲ مگابایت پر شده؛ کد سبک‌تر یا پلن بزرگ‌تر |

## اجرای محلی برای تست

```bash
EXEC_TOKEN=یک_رشته_بلند_تصادفی_دلخواه node server.js
curl http://localhost:10000/health
```
